# Factorization

소인수분해를 핵심 규칙으로 삼은 3D 자동화 게임. three.js + 직교 투영 카메라, 데스크톱 브라우저 전용.

기획서: [docs/GDD.md](docs/GDD.md)

## 실행

```bash
npm install
npm run dev
```

| 명령 | 설명 |
| --- | --- |
| `npm run dev` | 개발 서버 (HMR) |
| `npm run test` | 시뮬레이션 · 입력 · 아키텍처 테스트 |
| `npm run typecheck` | 타입 검사 |
| `npm run build` | 타입 검사 후 `dist/` 로 정적 빌드 |

## 구조

GDD 14.2의 계층 규칙을 따릅니다. `sim/`·`core/`·`data/`·`input/`·`factor/`는 **렌더러를 import하지 않으며**, `tests/architecture.test.ts`가 이를 강제합니다.

이건 이론이 아니에요 — 렌더러를 Phaser/2D에서 three.js/3D로 바꾸면서 저 네 계층은 한 줄도 건드리지 않았습니다.

```
src/
  config.ts       타일 크기, 카메라 각도·줌 범위, 시뮬 틱
  core/           순수 계산 — grid(타일↔3D), dir(방향), line(드래그 경로), rng(시드), clock(시간→틱)
  factor/         소수 서명 · 레시피북(검증·트리·요구량) · 인수분해 뷰 모델
  sim/            월드 · 벨트 · 채굴기 · 기계 · 시브 · 건설비(Builder) · 시뮬레이션 루프 · 맵 생성
  data/           건물·아이템·레시피·시작 재고 (밸런싱용 데이터)
  input/          InputAdapter (마우스·키보드), Command 패턴 실행 취소
  runtime/        백그라운드에서도 도는 워커 타이머
  render/         three.js 씬, 직교 궤도 카메라, InstancedMesh (건물·벨트·아이템·상태등)
  ui/             DOM HUD 오버레이 (재고·검사 패널·인수분해 뷰)
tests/
```

### 알아둘 것

- **그리드** (`core/grid.ts`): 타일은 XZ 평면에 축 정렬, Y가 위. 타일 `(x, y)`는 월드 X `[x, x+1)`, Z `[y, y+1)`를 차지하므로 피킹은 `floor`입니다 (2D 아이소 시절엔 다이아몬드가 정수 좌표를 중심으로 해서 `round`였어요).
- **카메라** (`render/CameraRig.ts`): 직교 투영이라 **줌은 거리가 아니라 절두체 크기**입니다. 카메라는 타깃에서 항상 `CAMERA_DISTANCE`만큼 떨어져 있어요. 이 때문에 맵 단위로 잡은 Fog는 씬 전체를 덮어버립니다 — 쓰려면 카메라 거리 기준으로 잡으세요.
- **z-fighting**: 광석 데칼은 지면과 거의 같은 평면이라 얕은 각도에서 깨집니다. polygon offset + 좁은 깊이 버퍼 범위 + 상하각 하한 22°로 막았습니다.
- **드래그 건설** (`core/line.ts`): 포인터는 샘플만 보고하므로 샘플 사이를 메웁니다. 건물은 Bresenham(`tileLine`)이지만 **벨트는 `walkGrid`** 로 4방향 연결 경로만 씁니다 — 벨트는 변으로 맞닿은 타일에만 아이템을 넘길 수 있어서, 대각선 한 칸이 있으면 아이템이 건너지 못하는 틈이 생기기 때문이에요.
- **깊이 정렬 코드는 없습니다.** z-buffer가 합니다.

## 첫 공장 만들기

시작 재고는 철판 100, 구리판 20, 돌 20입니다. 건물마다 값이 있고(버튼에 표시), 철거하면 **전액 환불**돼요.

1. **채굴기**를 광석 위에 놓습니다 (철광석은 시브 서쪽 `x≈58`에 있어요).
2. **컨베이어**를 채굴기 옆에서 **제련로**까지 드래그합니다. 드래그 방향으로 자동으로 놓이고, 꺾어 그으면 코너가 이어져요.
3. **제련로**를 놓고 **클릭**하면 오른쪽에 검사 패널이 열립니다. 레시피를 `철판`으로 고르세요. (새로 놓는 제련로는 마지막에 고른 레시피로 시작해요.)
4. 제련로 출력을 컨베이어로 **시브**까지 잇습니다. 좌측 시브 재고에 철판이 늘고 분당 속도가 표시돼요.
5. 기계 위의 **상태등**을 보세요: 🟢 작동 · 🟡 재료 대기 · 🔴 출력 막힘 · ⚪ 레시피 없음.
6. **T** 키(또는 ∏ 버튼)로 **인수분해 뷰**를 엽니다. 게이트 부품을 골라 분당 목표를 넣으면 필요한 원자재와 기계 대수가 나와요.

돌이 모자라면 **맨 광석 타일을 클릭**해서 직접 캐세요(도구를 든 상태가 아닐 때).

기계는 레시피에 필요한 것만 받아요. 엉뚱한 아이템이 오면 **벨트가 기계 앞에서 막힙니다** — 섞인 벨트를 정리하는 게 게임이에요.

## 현재 상태 — M2 완료

**M2에서 추가됨**
- **서명 시스템** (`factor/`): 원자재가 소수이고 제품의 서명은 재료 서명의 곱이라, 지수가 곧 원자재 소요량이에요. 레시피 타입에 **산출 개수 필드가 아예 없어서** 규칙 R1(레시피는 1개만 산출)이 검사가 아니라 타입으로 강제됩니다. GDD의 검산표를 독립 리터럴로 옮겨 대조하고, 서명 곱셈과 레시피 트리 순회라는 서로 무관한 두 방법으로 같은 결과가 나오는지 확인합니다.
- **제련로·조립기**: 재료를 거절하는 기계. 제작 시간을 정수 틱으로 세서 처리량이 정확해요(제련로 37.5개/분, 조립기 기어 60개/분).
- **분배기·언더패스**: 막힌 출구를 건너뛰는 3방향 분배, 다른 벨트를 가로지르는 지하 통과.
- **건설비·환불·수동 채굴**: 철거 취소도 다시 값을 내며, 재고가 모자라면 **취소가 실패**합니다(아니면 "철거 → 취소"로 돈이 복사돼요). **재고 + 지도 위 건물 값 = 처음 재고**라는 불변식을 4,000번의 무작위 작업으로 검증합니다.
- **화면**: 기계 상태등, 검사 패널(레시피·버퍼·진행도), 인수분해 뷰(서명 칩·재료 트리·필요 기계 대수).

**M1에서 구현됨**
- **시뮬레이션** (`sim/`): 벨트(타일당 4개, 간격 0.25, 6/s) · 채굴기(타일당 0.125/s, 지배 광석 선택, 버퍼 5, 출력 라운드로빈) · 시브(재고와 누적 납품 분리, 절대 입력을 막지 않음, 분당 속도)
- **렌더링**: 벨트 슬래브 + 방향 화살표, 아이템 전체가 InstancedMesh 하나 (드로우콜 1회), 틱 사이 보간
- **건설 UX**: 벨트 드래그 자동 방향, 꺾어 그으면 코너 자동 연결, 시브는 철거 불가
- **성능**: 5,252 벨트 · 10,504 아이템에서 헤드리스 **0.138ms/틱**(예산 10ms의 1.4%)

의도적으로 미룬 것: **교차기**(언더패스로 대체 가능), 인수분해 뷰의 **"현재 생산률과 비교"**(생산 통계가 필요), 언더패스 통과 지연.

아직 없음: **전력**(Mk2 기계라 강철·실리콘·프로세서 이후 레시피는 아직 못 돌려요), 미션(봉인), 세이브, 생산 통계. 건물은 박스 플레이스홀더입니다.

다음: **M3 — 전력·봉인(미션)·해금, 생산 통계, 검사 패널 확장.**

### 알아둘 것 (M2에서 배운 것)

- **부동소수 시간은 기계를 조용히 느리게 만듭니다.** 1/30을 30번 더해도 정확히 1.0이 안 돼서, 초 단위로 누적하면 한 틱씩 밀려요. 제작 시간은 `round(초 × TPS ÷ 속도)` **정수 틱**으로 셉니다.
- **테스트가 통과하는 것과 테스트가 지켜주는 것은 다릅니다.** 변이 검사(코드를 일부러 망가뜨려 테스트가 잡는지 확인)를 했더니, 분배기의 "들어온 쪽 제외" 규칙과 언더패스 입구의 순서 규칙을 **아무 테스트도 지키지 않고 있었어요.** 앞의 것은 "피더 벨트는 어차피 자기를 향해서 제외된다"는 이유로 공허한 테스트였고, 뒤의 것은 순서가 틀려도 처리량은 그대로라 처리량 테스트로 안 잡혔어요. 둘 다 다시 썼습니다.
- **엄격한 실행 취소는 재고를 정확히 복원합니다.** 그래서 "차단된 취소"는 재고가 **히스토리 밖에서** 줄 때만 생겨요. 무작위 테스트가 이 경로를 한 번도 안 타서 스스로 커버리지 가드에 걸렸습니다.

### 알아둘 것 (M1에서 배운 것)

- **벨트의 모든 진입은 `p=0`** 입니다. 뒤·옆·채굴기 모두요. 옆에서 들어온 아이템은 꺾인 경로(가장자리 → 중앙 → 출구)를 따라가서 곡선이 별도 상태 없이 나옵니다. 자세한 규칙은 GDD §7.1.
- **화살표 삼각형의 꼭짓점 순서는 반시계**여야 합니다. 양면 재질은 뒷면의 조명 법선을 뒤집어서, 시계 방향이면 화살표가 어둡게 렌더링돼요. 실제로 겪은 버그이고 `tests/render.test.ts`가 지킵니다.
- **마우스와 건물의 오프셋은 세 군데서 났습니다.** (1) **캔버스 크기**: `setSize(w, h, false)`가 CSS 크기를 지정하지 않아, 화면 배율이 100%를 넘으면 캔버스가 창보다 `배율`배 크게 표시돼 창 왼쪽 위에서만 맞고 오른쪽 아래로 갈수록 어긋났어요. **배율 100%에서는 절대 보이지 않는 버그**라 `render/viewport.ts`와 테스트로 고정했습니다. (2) **짝수 크기 건물**(채굴기·제련로)은 커서의 타일을 모서리로 삼아 항상 반 타일씩 비껴 있었고, 지금은 커서의 정확한 지면 좌표로 가장 가까운 타일 모서리에 앉습니다(`core/grid.ts`의 `footprintOrigin`). (3) 키 큰 건물의 미리보기는 화면 위로 솟아 보여서, 지면에 **발자국 판**을 함께 깔았습니다.
- **다른 탭·창을 봐도 공장은 계속 돕니다.** 브라우저는 안 보이는 탭의 `requestAnimationFrame`을 멈추고 타이머를 늦추기 때문에, 시뮬을 프레임에 붙이면 창을 가리는 순간 멈춰요. `runtime/heartbeat.ts`(웹 워커 타이머, 백그라운드에서도 안 늦춰짐)가 깨우고, `core/clock.ts`(`SimClock`)가 **실제 경과 시간으로 밀린 틱을 계산**합니다. 그래서 워커를 못 써서 일반 타이머로 폴백하거나 탭이 통째로 얼어도, 돌아왔을 때 밀린 만큼(최대 30분) 따라잡아요. 그동안 화면 상단에 `⏩ 따라잡는 중`이 표시됩니다.
- **탭이 숨겨지면 `requestAnimationFrame`이 멈춥니다.** 자동 검증 중 뷰포트가 0×0이 되기도 해서, 디버그 훅과 헤드리스 테스트를 함께 씁니다.
