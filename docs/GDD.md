## 1. 컨셉

### 1.1 한 줄 소개
> **게이트는 하나의 거대한 수(數)로 잠겨 있다. 그 수의 소인수분해가 곧 필요한 원자재 목록이다.**
> 광석을 캐고, 벨트로 나르고, 가공해서, 잠금 수를 구성하는 인수들을 직접 생산해내는 3D 자동화 게임.

### 1.2 테마가 게임이 되는 지점

이름만 *Factorization*인 게 아니라, **소인수분해가 실제로 동작하는 규칙**입니다.

1. **원자재 = 소수.** 철=2, 구리=3, 석탄=5, 돌=7, 모래=11, 석영=13.
2. **제품의 서명 = 재료 서명들의 곱.** 기어는 철판 2장이므로 `2 × 2 = 2²`.
3. **따라서 소인수분해의 유일성에 의해, 서명의 지수는 정확히 원자재 소요량이다.**
   `기계 프레임 = 2⁴·5²·7⁸` → 철 4, 석탄 2, 돌 8. 별도의 자재 명세 데이터가 필요 없고, **서명 자체가 명세**입니다.
4. **게이트의 잠금 수는 천문학적으로 커서 숫자로는 쓸 수 없다.** 오직 인수분해된 형태로만 읽힌다 — 이것이 게임의 화면이자 주제입니다.

### 1.3 디자인 필러
1. **보이는 흐름** — 아이템이 어디서 어디로 얼마나 흐르는지 한눈에 읽혀야 한다.
2. **작은 손, 큰 공장** — 드래그 건설·복사·블루프린트를 초반부터 제공한다.
3. **병목은 플레이어가 찾는다** — 정답을 알려주지 않고, 진단 도구를 준다.
4. **안전한 실패** — 전투도 영구 손실도 없다. 100% 환불 철거, 소프트락 없음.
5. **읽히는 3D** — 3D는 카메라 자유를 위한 것이지 몰입을 위한 것이 아니다. 원근 왜곡으로 공장이 안 읽히기 시작하면 그 기능은 뺀다. (§4.1)

### 1.4 타깃 / 플레이타임
- 타깃: 자동화 게임 입문~중급자. Factorio는 부담스럽지만 그 재미는 원하는 사람.
- 첫 클리어 8~10시간, 이후 엔드리스(계약 모드).

|---|---|---|

## 2. 세계관

궤도에서 내려온 자동 공장 유닛이 버려진 행성에 착륙한다. 지표에는 봉인된 **게이트**가 있고, 그 표면에는 인수분해된 형태의 잠금 수가 새겨져 있다. 유닛은 중앙 시설 **시브(Sieve)** 를 통해 자재를 받아 공장을 짓고, 잠금 수의 인수들을 하나씩 채워 넣는다.

스토리는 미션 사이 짧은 텍스트 로그로 최소화한다.

## 3. 코어 루프

```
[초 단위]  자원 패치에 채굴기 배치 → 벨트로 연결
[분 단위]  가공 기계 배치 → 레시피 설정 → 비율 맞추기 → 시브로 납품
[시간 단위] 봉인 해제 → 신규 건물/레시피 해금 → 공장 확장·재설계
[세션 단위] 병목 진단 → 리팩터링 → 새로운 소수(신규 원자재) 진입
```

**감정 곡선**: 첫 5분 안에 "채굴→벨트→숫자 상승"을 경험시키고, 이후 30분마다 새로운 문제(분배 → 전력 → 실리콘 → 원거리 수송)를 하나씩 던진다. 새 원자재는 곧 **새 소수의 등장**으로 연출된다.

## 4. 월드

### 4.1 그리드 / 카메라 규칙

- **논리 좌표**: 정사각 타일 그리드 `(x, y)`. 3D에서는 XZ 평면에 축 정렬로 놓이고 **Y가 위**다. 타일 `(x, y)`는 월드 X `[x, x+1)`, Z `[y, y+1)`를 차지한다.
- **좌표 변환**: 투영 수학이 필요 없다. 타일 중심은 `(x+0.5, 0, y+0.5)`, 피킹은 지면 평면에 레이캐스트 후 `floor`.
  - *2D 시절과 반올림이 다르다*: 다이아몬드는 정수 좌표를 **중심**으로 한 칸이라 `round`였지만, 지금은 타일이 자기 좌표에서 **시작**하는 칸이라 `floor`다.
- **카메라 — 직교(orthographic) 투영**: 자유로운 좌우 회전(Q/E 누르는 동안 연속), 상하 각도 22°~85°, 줌은 화면에 담기는 타일 수(8~180).
  - **원근이 아니라 직교인 이유**: 필러 1번이 "보이는 흐름"인데 원근 왜곡과 가림이 정확히 이를 방해한다. 직교는 아이소메트릭의 가독성을 유지하면서 3차원이 주는 자유 회전만 취한다. Factorio가 2D를 고수하는 이유와 같은 판단이다.
  - 기본 각도는 `atan(1/√2)` ≈ 35.26° — 세 축의 단축이 같은 **진짜 아이소메트릭 각도**로, 2D 시절이 흉내내던 바로 그 각도다.
  - **상하각 하한 22°**: 수평선에 가까운 시점은 공장 대부분을 앞 건물 뒤로 숨기고, 지면 데칼이 깊이 버퍼를 스치게 한다.
  - 직교 카메라는 거리로 축척이 정해지지 않으므로 **줌 = 절두체 크기**이고, 카메라는 타깃에서 고정 거리에 있다. 이 때문에 맵 단위로 지정한 안개(Fog)는 씬 전체를 덮어버린다 — 쓰려면 카메라 거리 기준으로 써야 한다.
- **깊이 정렬 없음**: z-buffer가 처리한다. 2D의 페인터 알고리즘이 통째로 사라졌고, 이것이 3D 전환의 가장 큰 단순화다.
  - 단, 지면과 거의 같은 평면인 **광석 데칼은 polygon offset**으로 분리한다. 얕은 각도에서 z-fighting이 난다.
  - 깊이 버퍼 범위는 맵 대각선 기준으로 좁게 잡는다. 직교 깊이는 선형이라 정밀도가 `범위/2^24`로 균일하다.
- **고도 없음**: 절벽·다층 없음. 지형은 평면이고 건물만 높이를 갖는다.
- **건물 회전**: 4방향. 3D에서는 메시 하나를 Y축으로 돌리면 되므로 **방향별 에셋이 필요 없다** — 2D였다면 회전 1종당 스프라이트 4장이 필요했다.
- **가림 문제**: 큰 건물 뒤가 안 보이면 카메라를 돌리면 된다. 이것이 3D로 옮긴 직접적인 동기다.

## 5. 소수 서명 시스템 (핵심)

### 5.1 정의
모든 아이템은 양의 정수 **서명(signature)** 을 갖는다.

- 원자재의 서명 = 배정된 소수.
- 제품의 서명 = `Π(재료 서명 ^ 소요 개수)`.

### 5.2 설계 규칙 R1 — 모든 레시피는 1개를 산출한다
서명이 정수로 유지되려면 이 규칙이 필요하다. 산출이 2개인 레시피(예: 구리판 1 → 전선 2)가 있으면 서명이 `3^(1/2)`처럼 유리수 지수가 되어 인수분해가 깨진다.

- **비용**: Factorio식 "×2 산출로 벨트 부하를 줄이는" 설계를 쓸 수 없다.
- **보완**: 그런 중간재(전선 등)는 **제작 시간을 짧게**(0.5s) 잡아 기계 수 부담을 낮춘다. 벨트 압력이 올라가는 만큼 벨트 티어 업그레이드의 가치가 커진다 — 의도된 트레이드오프.
- 이 규칙은 **밸런싱 도구가 아니라 시스템의 전제**이므로, 레시피 추가 시 자동 검증 테스트로 강제한다.

### 5.3 표기
지수가 크므로 정수는 절대 표시하지 않고 **인수분해 형태로만** 표시한다.

```
기어           2²
회로           2 · 3²
기계 프레임     2⁴ · 5² · 7⁸
게이트 부품     2⁴⁰ · 3⁷² · 5⁴⁰ · 7¹⁶ · 11⁶⁴ · 13⁴
```

UI에서는 소수마다 **자원 색 + 아이콘**을 입혀 표시한다 (`2⁴⁰`의 2는 철 색). 숫자를 못 읽어도 색 덩어리 크기로 "구리가 제일 많이 든다"가 읽히게 한다.

### 5.4 인수분해 뷰 (핵심 UI)
서명 시스템이 실제로 쓸모 있어지는 지점. 아무 제품이나 탭/클릭하면:

1. 서명을 **재귀 트리**로 펼친다: `게이트 부품 = 파워 코어 × 로직 코어 × 기계 프레임²` → 각 항을 다시 전개 → 원자재까지.
2. **목표 분당 생산량**을 입력하면 필요한 채굴기·제련로·조립기 **대수를 자동 계산**한다.
3. 현재 공장의 실제 생산률과 비교해 **부족한 단계를 붉게 표시**한다. *(M2에서는 1·2번까지 구현. 3번은 생산 통계가 필요해 M3.)*

**M2 구현**: 서명을 소수별 칩(원자재 색 + 이름)으로, 한 단계 방정식(`게이트 부품 = 파워 코어 × 로직 코어 × 기계 프레임²`)과 재귀 재료 트리, 그리고 **분당 목표를 넣으면 품목별 필요량과 기계 대수**(소수점 정확값은 툴팁, 표에는 올림)를 보여준다. 원자재 행은 필요한 채굴기 수(광석 4칸 기준). 계산은 전부 `factor/view.ts`의 순수 함수라 화면과 무관하게 테스트된다. `T` 키 또는 ∏ 버튼.

이것이 §1.3 필러 3(병목 진단)의 주력 도구이자 테마의 실사용처다. 외부 비율 계산기를 열 필요가 없다.

|---|---|---|---|---|---|
| 2 (철) | 16 | 16 | 8 | **40** | 철 40 |
| 3 (구리) | 16 | 56 | 0 | **72** | 구리 72 |
| 5 (석탄) | 12 | 24 | 4 | **40** | 석탄 40 |
| 7 (돌) | 0 | 0 | 16 | **16** | 돌 16 |
| 11 (모래) | 16 | 48 | 0 | **64** | 모래 64 |
| 13 (석영) | 0 | 4 | 0 | **4** | 석영 4 |
| | | | | **236** | |

원자재 경로 재계산으로 교차 검증: 파워 코어 = 철16·구리16·석탄12·모래16, 로직 코어 = 철16·구리56·석탄24·모래48·석영4, 기계 프레임 = 철4·석탄2·돌8. 일치.

**최종 목표 부하** (§9의 Lv20 = 6개/분 유지 기준):
`236 × 6 = 1,416 원자재/분 ≈ 23.6/s`
→ 철 4/s, 구리 7.2/s, 석탄 4/s, 돌 1.6/s, 모래 6.4/s, 석영 0.4/s
→ 채굴기 Mk3(2.25/s) 약 13기 + 제련·조립 라인. 설계 실력을 요구하되 한 화면에 담기는 규모.

> 구리 소요량이 가장 크다(72/236). 의도적으로 철 중심 관성을 깨서, 중반 이후 구리 라인 증설이 별도의 과제가 되게 했다.

### 5.6 완전거듭제곱 계약 (엔드리스 전용 · 제안, 검증 필요)
지수 = 원자재 수량이므로, **"납품 묶음 전체의 서명이 완전세제곱이 되게 하라"** = 모든 소수의 지수를 3의 배수로 맞추라는 뜻이 된다. 아이템 N개를 납품하면 지수가 N배되므로, 여러 품목의 수량을 조합해 **법 3 연립을 푸는** 작은 수학 퍼즐이 된다.

- 본편 진행에는 **넣지 않는다** (진입장벽). 엔드리스 계약의 한 종류로만 제공.
- 게임 내에서 "지수를 3의 배수로" 형태로 안내하고, 해가 존재하도록 계약을 생성한다.
- 재미가 검증되지 않았으므로 **후순위 실험 기능**으로 분류.

### 6.2 기계 입출력 규칙 (인서터 없음)
- **입력**: 기계를 향한 컨베이어에서 자동 수령. 레시피에 필요한 것만 수락 → 불필요한 아이템은 벨트에서 막힌다(분류기로 푸는 것이 의도된 과제).
- **출력**: 기계를 향하지 **않는** 인접 컨베이어로 배출. 여러 개면 라운드로빈.
- **버퍼**: 재료별 요구량의 2배, 출력 2회분. 가득 차면 `출력 막힘`.
- **상태 표시**: `▶ 작동` / `⏸ 입력 부족` / `⛔ 출력 막힘` / `⚡ 전력 부족`. 줌아웃 시 색 점으로 축약.

**M2 구현 노트**
- **거절이 설계의 핵심이다.** 기계는 레시피의 재료만, 그것도 1회분의 2배까지만 받는다. 벨트가 엉뚱한 아이템을 나르면 기계 문 앞에서 멈춰 **뒤의 줄 전체가 막힌다**(버려지지 않는다). 섞인 벨트를 정리하는 것이 플레이어의 과제다.
- **제작 시간은 초가 아니라 정수 틱**이다. 1/30을 30번 더해도 정확히 1.0이 되지 않아 부동소수 누적은 한 틱씩 밀려 기계가 조용히 몇 % 느려진다. 제작은 `round(초 × TPS ÷ 속도)`틱이고, 끝나는 틱에 바로 다음 제작을 시작해 연속 제작이 정확히 그 간격으로 이어진다. 측정: 제련로 분당 37.5개(1.6초), 조립기 기어 분당 60개.
- **레시피는 월드 데이터**다(시뮬 상태가 아니다). 재빌드와 저장을 견디고, 실행 취소된다. 레시피를 바꾸면 기계는 비워진 채 새로 시작한다(들고 있던 재료는 다른 용도였으므로). 기계 등급을 넘는 레시피(Mk1 제련로에 강철)나 다른 종류의 레시피는 무시된다.
- 새 기계는 **같은 종류에 마지막으로 지정한 레시피**로 시작한다(제련로 여러 대를 깔 때 일일이 지정하지 않도록). 배치와 같은 실행 취소 단계에 묶인다.
- 기계 위의 **상태등**: 초록 작동 / 노랑 재료 대기 / 빨강 출력 막힘 / 회색 레시피 없음. 노랑·빨강이 문제의 위치다.
- 기계를 클릭하면 **검사 패널**이 열린다: 상태, 레시피 목록(서명 포함), 재료 버퍼, 제작 진행도, 출력 대기량.

### 6.3 시브(허브) 규칙
- 아이템 수령 시 **재고 저장 + 누적 납품 카운터 증가**를 동시에, 그러나 **분리해서** 처리한다.
  - 건설은 **재고**를 소모, 봉인 해제는 **누적 납품량**을 본다 → 건설해도 진행도가 줄지 않는다.
- **시브는 절대 입력을 막지 않는다.** 재고 상한(9,999) 초과분은 폐기하되 누적 카운터에는 반영 → 허브 앞 벨트 정체가 구조적으로 발생하지 않는다.
- **수동 채굴**: 광석 타일 탭/클릭 시 재고 +1 (소프트락 방지). 철거 시 건설비 100% 환불.

**M2 구현 노트 — 경제의 정합성**
- 시작 재고: 철판 100, 구리판 20, 돌 20. 판은 채굴이 아니라 제련으로만 나오므로 시작 재고 없이는 아무것도 지을 수 없다. 수동 채굴은 재고에만 더하고 **누적 납품에는 세지 않는다**(생산이 아니므로 봉인 진행을 앞당기면 안 된다).
- **무엇이든 공짜로 되돌릴 수 없다.** 철거가 100% 환불이므로 철거 취소는 같은 값을 다시 내야 한다. 아니면 "철거 → 취소"로 돈을 복사한다. 그 사이 재고를 써버렸다면 **취소가 실패**한다. 명령이 성공/실패를 알고, 실패한 명령은 스택에 남아 재고가 회복되면 다시 시도할 수 있다.
- 드래그로 지은 벨트 묶음은 **전부 아니면 전무**다. 일부가 실패하면 이미 적용한 것을 되돌린다(중간이 빠진 벨트는 아이템이 못 건넌다).
- 불변식(테스트로 고정): **재고 + 지도 위 모든 건물의 값 = 처음 재고.** 4,000번의 무작위 건설·철거·취소·재실행 뒤에도 성립한다.
- 남은 소프트락 위험: 플레이어가 철판을 전부 쓰고 제련로가 하나도 없으면 철판을 만들 방법이 없다. 100% 환불로 회복 가능하고 드물지만, 수동 채굴은 광석만 주므로 완전한 해결은 아니다.

## 7. 물류 시스템

### 7.1 컨베이어 모델 (단일 레인)
- 타일당 최대 4개, 아이템 위치 `p ∈ [0,1]`, 최소 간격 0.25.
- 속도: Mk1 1.5 tiles/s (6/s), Mk2 3.0 (12/s), Mk3 4.5 (18/s).
- **진입 규칙 (M1 구현에서 확정)**: 벨트로 들어오는 **모든 경로(뒤·옆·채굴기)가 `p=0`으로 진입**한다. `p=0`은 가능한 가장 작은 위치라 진입은 항상 맨 뒤에 붙이는 것이고 정렬 삽입이 필요 없다. 초안의 "옆에서 `p=0.5`에 삽입"은 폐기했다 — 아이템이 반 칸 순간이동하고 T자 합류가 어색했다.
- **곡선은 상태가 아니라 경로다**: 옆에서 들어온 아이템은 꺾인 경로(옆 가장자리 → 중앙 → 출구)를 따라간다. 곡선 벨트를 위한 타일별 상태가 필요 없고, 직진 이어붙임과 같은 규칙으로 동작한다. 아이템마다 진입 방향(`lat`)만 기억한다.
- **합류 우선순위**: 직진 공급이 옆 공급보다 먼저 자리를 차지한다(갱신 순서에서 뒤쪽 이웃을 먼저 처리). 옆 공급은 직진 흐름의 **빈틈에만** 끼어든다. 직진이 절반만 차 있으면 옆이 나머지를 채운다.
- **정체**: 앞이 막히면 뒤도 멈춘다(압축 정체, 타일당 `1, .75, .5, .25` 위치에 4개). 병목을 눈으로 읽게 하는 핵심 신호.
- **갱신 순서**: **하류 → 상류**(BFS). 그래야 막힌 줄이 한 틱에 앞에서부터 풀린다 — 반대 순서면 빈자리가 틱당 한 칸씩만 전파되어 처리량이 떨어진다.
- **루프**: 순환 벨트는 어떤 출구에서도 도달되지 않아 갱신 순서가 없다. 순서 끝에 타일 번호 순으로 붙이며, 고정 순서면 결정적이다. (루프 위 아이템이 한 틱에 두 번 움직일 수 있으나 간격·보존 불변식은 깨지지 않는다.)
- **허용 오차**: 위치를 float32로 저장하고 0.05씩 더하므로 몇 ×1e-7씩 어긋난다. 간격 판정에 `1e-3` 허용을 두지 않으면 정확히 0.25 간격인 아이템이 타일 경계에서 거절되어 6/s에 못 미친다.
- **화면 보간**: 시뮬은 30 TPS, 화면은 그보다 빠르다. 틱 시작 위치(`prev`)와 현재 위치 사이를 그린다. 타일을 넘어갈 때 `prev`를 다음 타일 기준으로 환산(`prev - 1`)해서 경계에서 끊기지 않는다.
- *단일 레인 결정 이유*: 구현·학습 비용이 낮다. 2레인은 피드백 후 재검토(§16).

**측정 (M1, 5,252 벨트 · 10,504 아이템)**: 헤드리스 틱당 **0.138ms**(예산 10ms의 1.4%), 편집 후 전체 재구축 0.88ms. 브라우저(JIT 콜드 포함) 약 0.47ms/틱. 아이템 보존·간격·6/s 처리량은 테스트로 고정.

### 7.2 물류 부품
| 부품 | 동작 |
|---|---|
| 분배기 | 입력 반대 3방향 라운드로빈. 막힌 출구는 건너뜀. 역류 없음 |
| 교차기 | 직진 두 흐름이 섞이지 않고 통과 *(M2 범위에서 제외, 언더패스로 교차 가능)* |
| 언더패스 | 입구/출구 쌍. 지연 후 출구로 이동(지하 표시) |
| 분류기 | 지정 아이템 직진, 나머지 좌/우 |
| (후속) 오버플로 게이트 | 앞이 막히면 측면 우회 |

**M2 구현 노트**
- **분배기**는 아이템 1개를 들고, 매 틱 들어온 쪽을 뺀 세 방향을 마지막 위치부터 차례로 시도한다. 가득 찼거나 거절하거나 **자기를 향한 벨트**인 쪽은 건너뛴다. 막힌 출구가 나머지를 멈추지 않고, 전부 막히면 아이템이 그대로 남아 앞줄을 막는다(소실 없음). 분배기끼리 이으면 서로 되돌려 보내 핑퐁하므로 **들어온 쪽 제외 규칙이 실제로 필요한 곳은 분배기 사이**다. 채굴기·기계도 벨트와 같은 포트 규칙으로 분배기에 내보낸다.
- **언더패스**는 입구·출구가 각각 방향 있는 벨트다. 입구는 **같은 방향을 보는 첫 출구**(앞쪽 5칸 이내)에 연결되고, 아이템은 한 번에 건너뛰어 사이에 지어진 것 위를 지나간다. 출구 하나는 입구 하나만 받는다(건설 순서로 결정, 결정적). 출구가 없는 입구는 평범한 벨트로 동작하고, 링크는 월드를 따라 움직인다(출구를 지웠다 되돌리면 끊겼다 이어진다). **지하 통과 지연은 구현하지 않았다**(0틱). 처리량·간격은 그대로 6/s.
- **갱신 순서**가 미묘했다. 벨트는 하류→상류로 갱신하는데, 분배기는 최대 3곳으로 내보내므로 출구 중 **처음 도달한 것 뒤에** 놓는다(다른 출구는 빈자리를 한 틱 늦게 본다 — 지연이 조금 늘 뿐 정확성은 그대로). 언더패스 입구는 출구와 인접하지 않아 이웃 탐색으로 못 찾으므로 명시적 역링크가 필요하다. 빠뜨리면 입구와 그 앞 벨트가 순환 벨트처럼 맨 뒤에 **타일 번호순(상류 먼저)** 으로 붙는데, 지연이 균일하면 정상 처리량이 유지돼서 처리량 테스트로는 안 잡힌다 — 체인 전체의 순서를 직접 검사하는 테스트를 두었다.
- 비용: 5,252 벨트 벤치마크 틱이 0.138 → 0.197ms(예산 10ms의 2%).

## 8. 전력 시스템

- **도입 시점**: Phase 1(Mk1)은 **무전력**. Phase 2에서 도입되고 Mk2부터 전력 필요 → 물류를 먼저 익힌 뒤 전력이 "업그레이드"로 다가온다.
- **네트워크**: 전력 기둥이 범위 내 건물·기둥을 자동 연결. 연결 그룹 = 하나의 전력망.
- **브라운아웃**: 발전 < 수요이면 만족률(`supply/demand`)만큼 **모든 기계가 비례 감속**. 즉시 정지하지 않는다 → 실패가 부드럽다(필러 4).
- **연료**: 연소 발전기는 벨트로 석탄을 받는다 → 석탄이 물류 대상이 된다. 250 PU ≈ 석탄 4/s → 태양광(Lv12)의 동기.
- **오버레이**: 전력망별 색상, 만족률, 발전/소비 그래프.

**M3 구현 노트**
- **초안의 "기둥당 최대 8연결"은 넣지 않았다.** 연결 수 상한은 정당한 이유(성능·가독성) 없이 "왜 안 이어지지?"라는 진단 불가능한 정전을 만든다. 대신 기둥 범위가 겹치기만 하면 무제한으로 이어진다. 전력망 병합은 Union-Find로 결정적이다(건물 나열 순서와 무관 — undo/redo가 끝에 재삽입해도 같은 그룹이 나온다).
- **만족률은 정수 천분율**(`POWER_FULL = 1000`)이다. 소수(0.6)로 들고 있으면 "60%의 60%"가 반복 곱셈 오차로 서서히 어긋난다. 기계는 매 틱 만족률만큼 **정수 크레딧**을 적립하고 1000을 채운 틱에만 일한다 — 100%는 매 틱 정확히 1크레딧씩 쌓여 매번 일하는 특수한 경우가 된다.
- 건물이 두 전력망의 범위에 겹치면 **더 가까운 기둥** 쪽에 붙는다. 거리가 같으면 기둥 id가 낮은 쪽(먼저 지은 것)으로 결정적으로 붙는다.
- 오버레이(전력망 색상, 만족률 그래프)는 아직 없다. HUD에는 전력을 쓰는 건물에 커서를 올리면 "⚡ 전력 부족 83%" 같은 문구가 뜬다.

**M3 구현 노트 — 초안과의 차이, 그리고 왜**
- **핵심 규칙 하나를 새로 세웠다: 어떤 봉인이든, 그 요구를 채우는 데 필요한 레시피와 기계는 반드시 그 봉인이 열리기 *전*에 이미 해금되어 있어야 한다.** 초안 표는 이 규칙을 안 지켰다 — 예를 들어 Lv6이 "돌 벽돌 50"을 요구하는데 돌 벽돌 레시피를 여는 곳이 표 어디에도 없었고, 모터·기계 프레임·배터리·광학 렌즈·프로세서·파워 코어도 마찬가지였다. 그래서 이번 표는 그런 레시피들을 **그것을 요구하는 봉인의 한 칸 앞**으로 당겨 열었다(돌 벽돌은 Lv5, 모터는 Lv7, 기계 프레임은 Lv8 등). `tests/seals.test.ts`가 전 구간에서 이 규칙을 구조적으로 증명한다 — 수치를 나중에 조정해도 깨지면 테스트가 바로 잡는다.
- **아직 없는 건물이 해금 칸에서 빠졌다**: 교차기, 분류기, 컨베이어 Mk2/Mk3, 채굴기 Mk3, 태양광 패널, 배터리 뱅크, 전력·처리량 오버레이, 블루프린트. 해당 봉인은 지금은 그 칸이 비어 있고, 건물이 실제로 생기는 마일스톤에서 자기 봉인의 해금 칸으로 들어간다.
- **소수 도입 순서가 페이즈 표(§9.1)와 맞아떨어진다**: 2(Lv1)·3(Lv3) → 5(Lv5)·7(Lv6) → 11(Lv9) → 13(Lv13). 이건 손으로 맞춘 게 아니라 위 표에서 그대로 유도된다 — 각 봉인의 요구 항목을 서명으로 분해했을 때 처음 등장하는 소수가 그 봉인의 "새로운 소수"이고, `newPrimesOf()`가 이걸 계산해 온보딩 문구("새로운 소수: 5")에 쓴다.
- **지속 납품(Lv20)은 최근 60초의 납품량을 스냅샷 두 개로 비교**한다(`Sieve.deliveredInLastMinute`, M2의 분당 생산량과 같은 원리 — 진행 중인 1초를 세면 수치가 흔들린다). 60초 창이 그 분당 목표를 채운 매 초마다 카운터가 1씩 오르고, **단 1초라도 못 채우면 0으로 되돌아간다** — "5분간 유지"가 문자 그대로 끊김 없는 5분이 되도록.
- **건설·레시피 해금은 `Builder`가 막는다**: 잠기지 않은 것만 `checkPlacement`가 통과시키고(막히면 사유 `locked`가 "재고 부족"과 같은 자리에 뜬다), 레시피 지정은 `SetRecipeCommand`가 실패하면 실행 취소 스택에 아예 기록되지 않는다 — 실패한 명령이 스택에 남아 나중에 재시도되는 재고 부족 경로(§6.3)와는 다르다. 잠긴 레시피는 검사 패널의 레시피 목록에서 아예 **빠진다**(회색으로 보여주고 클릭을 막는 대신): 클릭했는데 아무 반응이 없는 것보다, 아직 없는 레시피가 안 보이는 편이 명확하다.
- 봉인 완료 시 HUD 힌트에 "🔓 봉인 N 달성 — 새로운 소수: … · 해금: …"이 한 줄 뜬다(§11.3의 온보딩 비트). 건설 바 버튼은 그 틱에 바로 잠금이 풀린 모습으로 바뀐다.

### 9.3 엔드리스 (계약 모드)
Lv20 이후 무작위 계약 생성:
- **지속 납품 계약**: "X를 분당 N개, M분간" — 기본형.
- **완전거듭제곱 계약**: §5.6 — 실험 기능.
난이도는 완료 횟수에 비례해 상승. 보상은 재고/코스메틱.

| 팬 | 좌드래그(도구 미선택) · WASD · 방향키 |

### 12.2 화면 버튼
키보드 단축키에는 전부 대응하는 화면 버튼을 둔다. 터치 때문이 아니라 **발견 가능성** 때문이다 — 단축키만 있으면 아무도 시점 회전이 있다는 걸 모른다.

### 12.3 세이브
- IndexedDB. 자동 저장 60초 + 탭 종료 직전.
- **내보내기/가져오기(파일·문자열)** 로 기기 간 이동. 계정 기반 클라우드 동기화는 1.0 제외.

## 13. 아트 · 오디오

### 13.1 아트 방향
- **깔끔한 벡터풍 산업 스타일**: 낮은 채도 지면 + 높은 채도 아이템/기계 → 작은 화면에서도 판독 가능.
- 건물은 실루엣 + 컬러 캡으로 구분(제련로=주황 굴뚝, 조립기=청색 팔).
- **소수 모티프**: 아이템 아이콘 귀퉁이에 소수 배지. UI 폰트는 지수 표기가 또렷한 것으로.
- **제작 파이프라인**
  1. 프로토타입: 절차적 드로잉(플레이스홀더).
  2. 이후: Blender 4방향 프리렌더 또는 CC0 아이소 팩.
  3. 스프라이트 아틀라스 1~2장으로 배칭.
- **줌아웃 판독성을 아트 승인 기준에 포함** — 최대 줌아웃에서 기계 종류가 구분되지 않으면 반려.

### 13.2 오디오
- 기계 수에 비례하는 앰비언트 험, 배치/철거/해금 효과음, 봉인 해제 스팅.
- 브라우저 정책상 무음으로 시작하고 첫 입력에서 오디오 컨텍스트를 연다.

## 14. 기술 설계

### 14.1 스택
| 영역 | 선택 |
|---|---|
| 언어 | TypeScript (strict) |
| 번들러 | Vite |
| 렌더 | **three.js** (WebGL) |
| 입력·오디오·루프 | 직접 구현 — three.js는 엔진이 아니라 렌더러다 |
| UI | DOM 오버레이 (반응형·접근성·i18n에 유리) |
| 테스트 | Vitest (시뮬·입력·아키텍처 경계) |
| 배포 | 정적 호스팅 (GitHub Pages / itch.io) |

> **시뮬과 렌더는 완전히 분리**한다. 이건 이론이 아니다 — 이 경계 덕분에 렌더러를 Phaser에서 three.js로 바꾸면서 `sim/`·`data/`·`core/line.ts`·`core/rng.ts`·`input/commands.ts`를 한 줄도 건드리지 않았다. `tests/architecture.test.ts`가 이를 강제한다.

### 14.2 구조
```
src/
  sim/          ← 순수 TS. 렌더러 import 금지. 결정적(deterministic)
    world.ts        타일 그리드, 청크
    belts.ts        컨베이어 세그먼트 시뮬레이션
    machines.ts     기계 상태머신
    power.ts        전력망 분할·만족률
    sieve.ts        재고 / 누적 납품 / 봉인
    save.ts         직렬화·마이그레이션
  factor/       ← 서명 시스템 (sim·UI·툴이 공유)
    signature.ts    서명 계산, 곱/거듭제곱, 인수분해 표기
    solver.ts       목표 생산량 → 기계 대수, 병목 판정
  data/         ← 데이터 주도. 코드 수정 없이 밸런싱
    items.ts / recipes.ts / buildings.ts / seals.ts
  core/         ← 순수 계산. grid(타일↔3D), line(드래그 경로), rng(시드)
  render/       ← three.js 씬, 직교 궤도 카메라, InstancedMesh, 오버레이
  ui/           ← DOM HUD 오버레이
  input/        ← InputAdapter (마우스·키보드) + Command 패턴
  tools/        ← 밸런스 계산기, 맵 시드 미리보기
tests/
```

### 14.3 시뮬레이션 핵심
- **고정 30 TPS**, 렌더 60fps + 보간.
- **시뮬은 프레임에 매달리지 않는다** (M1 이후 확정). 브라우저는 숨겨진 탭의 애니메이션 프레임을 멈추고 타이머를 초당 1회 이하로 늦추므로, "프레임당 1틱"으로 돌리면 창을 가리는 순간 공장이 멈춘다. 그래서:
  - **`SimClock`이 실제 경과 시간으로 밀린 틱 수를 계산**한다. 프레임 60Hz든, 타이머 1Hz든, 워커 30Hz든 공장 속도가 같다.
  - **웹 워커 타이머(`Heartbeat`)가 30Hz로 메인 스레드를 깨운다.** 워커 타이머는 백그라운드에서도 늦춰지지 않는다. 워커를 못 쓰면 일반 타이머로 폴백하고, 이때도 `SimClock`이 밀린 시간을 정확히 따라잡는다.
  - **밀린 시간은 두 종류로 구분한다.** 짧은 간격의 누적(*live*)은 1초로 상한을 두어 초과분을 버린다 — 기계가 느리면 게임이 슬로모션이 되지, 영원히 빚을 쫓지 않는다. 한 번의 긴 간격(*away*: 탭이 얼었거나 기기가 잠듦)은 30분까지 전부 갚는다 — 공장은 그동안 계속 돌았어야 하니까.
  - 한 번에 쓰는 시간에는 **예산**이 있다(화면에 보일 때 10ms, 숨겨졌을 때 100ms). 따라잡기가 프레임 그리기를 굶기지 않고, 남은 건 다음 호출로 넘어간다.
  - 측정: 숨겨진 페이지 3초에 시뮬 틱 0 → 90(29.9/s). 메인 스레드를 4초 얼린 뒤 139틱으로 따라잡음(계속 돌았다면 138).
  - **알려진 한계**: 워커 타이머를 늦추지 않는 건 브라우저의 현재 동작이며 보장이 아니다. 브라우저가 탭을 완전히 얼리면(메모리 절약 모드 등) 돌아올 때까지 멈추고, 돌아온 뒤 30분까지 따라잡는다.
- **벨트 세그먼트화**: 연결된 직선 벨트를 하나의 라인으로 묶어 헤드부터 갱신.
- **활성 집합**: 정체/유휴 기계는 이벤트 발생 시까지 갱신 생략.
- **Command 패턴**: 모든 변경은 커맨드 → Undo/Redo, 이후 리플레이·Web Worker 이관 가능.
- **시드 RNG(mulberry32)**: 맵·계약 생성 결정적. 시드 공유.
- **서명 연산**: 큰 정수를 쓰지 않고 **소수별 지수 배열**(`Int32Array` 길이 6)로 표현한다. 곱셈=덧셈, 거듭제곱=스칼라 곱 → O(6). BigInt 불필요.

### 14.4 세이브
- JSON → LZ 압축 → IndexedDB. 자동 저장 60초 + 백그라운드 진입 시.
- `saveVersion` + 마이그레이션 체인. 밸런스·레시피 변경이 구버전 세이브를 깨뜨리지 않게.
- 서명은 **저장하지 않고 레시피에서 재계산** — 밸런스 변경 시 자동 반영.

### 14.5 성능 목표
데스크톱 전용이므로 상한이 v0.2보다 높다.

| 항목 | 목표 |
|---|---|
| 프레임 | 60fps |
| 규모 | 벨트 10,000타일 / 기계 1,000기 / 아이템 20,000 |
| 시뮬 1틱 | ≤ 10ms |
| 초기 로딩 | ≤ 3초 |
| 번들 | ≤ 5MB (현재 gzip 143KB) |

- **InstancedMesh가 기본**이다. 같은 종류의 벨트·기계·아이템은 드로우콜 하나로 묶는다.
- 벨트 위 아이템은 M1에서 단일 InstancedMesh + 프레임당 행렬 갱신으로 간다.
- 그림자는 기본 끔. 켠다면 카메라 타깃을 따라가는 좁은 범위로 한정한다.

### 14.6 테스트 전략
- 시뮬: 벨트 처리량, **아이템 보존(생성·소멸 없음)**, 루프 데드락 없음, 브라운아웃 비례 감속, 시브 비차단.
- **서명 불변식**: ① 모든 레시피는 산출 1개(규칙 R1) ② 서명에서 역산한 원자재 = 레시피 트리 전개 결과 ③ 잠금 수 = 요구 아이템 서명의 곱.
- 세이브 왕복, 시드 결정성.
- **아키텍처 경계**: `sim/`·`core/`·`data/`·`input/`이 렌더러를 import하지 않음을 테스트로 강제.
