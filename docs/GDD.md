## 1. 컨셉

### 1.1 한 줄 소개
> **게이트는 하나의 거대한 수(數)로 잠겨 있다. 그 수의 소인수분해가 곧 필요한 원자재 목록이다.**
> 광석을 캐고, 벨트로 나르고, 가공해서, 잠금 수를 구성하는 인수들을 직접 생산해내는 아이소메트릭 자동화 게임.

### 1.2 테마가 게임이 되는 지점

이름만 *Factorization*인 게 아니라, **소인수분해가 실제로 동작하는 규칙**입니다.

1. **원자재 = 소수.** 철=2, 구리=3, 석탄=5, 돌=7, 모래=11, 석영=13.
2. **제품의 서명 = 재료 서명들의 곱.** 기어는 철판 2장이므로 `2 × 2 = 2²`.
3. **따라서 소인수분해의 유일성에 의해, 서명의 지수는 정확히 원자재 소요량이다.**
   `기계 프레임 = 2⁴·5²·7⁸` → 철 4, 석탄 2, 돌 8. 별도의 자재 명세 데이터가 필요 없고, **서명 자체가 명세**입니다.
4. **게이트의 잠금 수는 천문학적으로 커서 숫자로는 쓸 수 없다.** 오직 인수분해된 형태로만 읽힌다 — 이것이 게임의 화면이자 주제입니다.

### 1.3 디자인 필러
1. **보이는 흐름** — 아이템이 어디서 어디로 얼마나 흐르는지 한눈에 읽혀야 한다.
2. **작은 손, 큰 공장** — 드래그 건설·복사·블루프린트를 초반부터 제공한다.
3. **병목은 플레이어가 찾는다** — 정답을 알려주지 않고, 진단 도구를 준다.
4. **안전한 실패** — 전투도 영구 손실도 없다. 100% 환불 철거, 소프트락 없음.
5. **한 손으로도 지어진다** — 모든 동작에 마우스/키보드와 터치 양쪽 경로가 있다. (§12)

### 1.4 타깃 / 플레이타임
- 타깃: 자동화 게임 입문~중급자. Factorio는 부담스럽지만 그 재미는 원하는 사람.
- 모바일에서 짧게, 데스크톱에서 길게 — 같은 세이브로 오가는 플레이.
- 첫 클리어 8~10시간, 이후 엔드리스(계약 모드).

### 1.5 레퍼런스
| 레퍼런스 | 가져올 것 | 버릴 것 |
|---|---|---|
| Factorio | 생산 통계, 비율 최적화, 블루프린트 | 전투/오염, 유체, 인서터, 손 제작 |
| Shapez | 허브 납품 기반 진행, 낮은 진입장벽 | 무한 단일 도형 조합 |
| Mindustry | 코어 재고로 건설비 지불, **검증된 모바일 조작** | 타워디펜스 |

## 2. 세계관

궤도에서 내려온 자동 공장 유닛이 버려진 행성에 착륙한다. 지표에는 봉인된 **게이트**가 있고, 그 표면에는 인수분해된 형태의 잠금 수가 새겨져 있다. 유닛은 중앙 시설 **시브(Sieve)** 를 통해 자재를 받아 공장을 짓고, 잠금 수의 인수들을 하나씩 채워 넣는다.

스토리는 미션 사이 짧은 텍스트 로그로 최소화한다.

## 3. 코어 루프

```
[초 단위]  자원 패치에 채굴기 배치 → 벨트로 연결
[분 단위]  가공 기계 배치 → 레시피 설정 → 비율 맞추기 → 시브로 납품
[시간 단위] 봉인 해제 → 신규 건물/레시피 해금 → 공장 확장·재설계
[세션 단위] 병목 진단 → 리팩터링 → 새로운 소수(신규 원자재) 진입
```

**감정 곡선**: 첫 5분 안에 "채굴→벨트→숫자 상승"을 경험시키고, 이후 30분마다 새로운 문제(분배 → 전력 → 실리콘 → 원거리 수송)를 하나씩 던진다. 새 원자재는 곧 **새 소수의 등장**으로 연출된다.

## 4. 월드

### 4.1 그리드 / 아이소메트릭 규칙
- **논리 좌표**: 정사각 타일 그리드 `(x, y)`.
- **화면 변환 (2:1 다이아몬드)**
  ```
  screenX = (x - y) * TILE_W / 2
  screenY = (x + y) * TILE_H / 2        // TILE_W=64, TILE_H=32, 에셋은 2배 해상도
  ```
- **고도 없음**: 절벽·다층 없음 → 깊이 정렬 단순화.
- **카메라**: 팬 + 줌(0.25× ~ 2×). **회전 없음** → 방향별 스프라이트 세트 불필요.
- **건물 회전**: 4방향. 벨트/기계는 방향별 스프라이트를 가진다.
- **렌더 레이어(아래→위)**: 지면 → 광석 데칼 → 벨트(평면) → 벨트 위 아이템 → 건물(`x+y` 정렬) → 오버레이 → UI.
- **가림 문제**: 건물 높이 최대 2타일. 커서/손가락 아래 건물은 반투명 처리.
- **피킹**: 스프라이트 픽셀이 아니라 **역변환한 타일 좌표**로 판정. 모바일은 터치 지점에 **±1 타일 관용 반경** 적용.

### 4.2 맵
| 항목 | 값 |
|---|---|
| 크기 (MVP) | 128×128 고정. 이후 청크(16×16) 기반 확장 |
| 생성 | 시드 기반 Simplex 노이즈 + 자원 패치 배치 규칙 |
| 지형 | 평지(건설 가능) / 물·암석(건설 불가) |
| 시작 위치 | 맵 중앙 시브, 반경 12타일 내 항상 평지 |

### 4.3 자원 배치
| 자원 | 소수 | 시브로부터 거리 | 패치 크기 | 도입 |
|---|---|---|---|---|
| 철광석 | **2** | 8~18 | 큼 | 시작 (시야 내 보장) |
| 구리광석 | **3** | 10~20 | 큼 | 시작 |
| 석탄 | **5** | 14~26 | 중 | Phase 2 |
| 돌 | **7** | 12~24 | 큼 | Phase 2 |
| 모래 | **11** | 28~45 | 중 | Phase 3 |
| 석영 | **13** | 45~65 | 작음 | Phase 4 (원거리 전진기지 유도) |

- 소수는 **희소성·도입 순서와 같은 방향으로** 배정했다. 큰 소수 = 늦게 등장 = 멀고 귀한 자원. 서명을 보면 난이도가 읽힌다.
- **매장량**: 기본 유한(타일당 200~800), "무한 광맥" 옵션 제공. 고갈 구현은 **베타 단계**(MVP는 무한).
- 채굴기는 덮은 광석 타일 수에 비례해 산출.

## 5. 소수 서명 시스템 (핵심)

### 5.1 정의
모든 아이템은 양의 정수 **서명(signature)** 을 갖는다.

- 원자재의 서명 = 배정된 소수.
- 제품의 서명 = `Π(재료 서명 ^ 소요 개수)`.

### 5.2 설계 규칙 R1 — 모든 레시피는 1개를 산출한다
서명이 정수로 유지되려면 이 규칙이 필요하다. 산출이 2개인 레시피(예: 구리판 1 → 전선 2)가 있으면 서명이 `3^(1/2)`처럼 유리수 지수가 되어 인수분해가 깨진다.

- **비용**: Factorio식 "×2 산출로 벨트 부하를 줄이는" 설계를 쓸 수 없다.
- **보완**: 그런 중간재(전선 등)는 **제작 시간을 짧게**(0.5s) 잡아 기계 수 부담을 낮춘다. 벨트 압력이 올라가는 만큼 벨트 티어 업그레이드의 가치가 커진다 — 의도된 트레이드오프.
- 이 규칙은 **밸런싱 도구가 아니라 시스템의 전제**이므로, 레시피 추가 시 자동 검증 테스트로 강제한다.

### 5.3 표기
지수가 크므로 정수는 절대 표시하지 않고 **인수분해 형태로만** 표시한다.

```
기어           2²
회로           2 · 3²
기계 프레임     2⁴ · 5² · 7⁸
게이트 부품     2⁴⁰ · 3⁷² · 5⁴⁰ · 7¹⁶ · 11⁶⁴ · 13⁴
```

UI에서는 소수마다 **자원 색 + 아이콘**을 입혀 표시한다 (`2⁴⁰`의 2는 철 색). 숫자를 못 읽어도 색 덩어리 크기로 "구리가 제일 많이 든다"가 읽히게 한다.

### 5.4 인수분해 뷰 (핵심 UI)
서명 시스템이 실제로 쓸모 있어지는 지점. 아무 제품이나 탭/클릭하면:

1. 서명을 **재귀 트리**로 펼친다: `게이트 부품 = 파워 코어 × 로직 코어 × 기계 프레임²` → 각 항을 다시 전개 → 원자재까지.
2. **목표 분당 생산량**을 입력하면 필요한 채굴기·제련로·조립기 **대수를 자동 계산**한다.
3. 현재 공장의 실제 생산률과 비교해 **부족한 단계를 붉게 표시**한다.

이것이 §1.3 필러 3(병목 진단)의 주력 도구이자 테마의 실사용처다. 외부 비율 계산기를 열 필요가 없다.

**최종 목표 부하** (§9의 Lv20 = 6개/분 유지 기준):
`236 × 6 = 1,416 원자재/분 ≈ 23.6/s`
→ 철 4/s, 구리 7.2/s, 석탄 4/s, 돌 1.6/s, 모래 6.4/s, 석영 0.4/s
→ 채굴기 Mk3(2.25/s) 약 13기 + 제련·조립 라인. 모바일에서도 감당 가능한 규모이면서 설계 실력을 요구하는 수준.

> 구리 소요량이 가장 크다(72/236). 의도적으로 철 중심 관성을 깨서, 중반 이후 구리 라인 증설이 별도의 과제가 되게 했다.

### 5.6 완전거듭제곱 계약 (엔드리스 전용 · 제안, 검증 필요)
지수 = 원자재 수량이므로, **"납품 묶음 전체의 서명이 완전세제곱이 되게 하라"** = 모든 소수의 지수를 3의 배수로 맞추라는 뜻이 된다. 아이템 N개를 납품하면 지수가 N배되므로, 여러 품목의 수량을 조합해 **법 3 연립을 푸는** 작은 수학 퍼즐이 된다.

- 본편 진행에는 **넣지 않는다** (진입장벽). 엔드리스 계약의 한 종류로만 제공.
- 게임 내에서 "지수를 3의 배수로" 형태로 안내하고, 해가 존재하도록 계약을 생성한다.
- 재미가 검증되지 않았으므로 **후순위 실험 기능**으로 분류.

### 6.2 기계 입출력 규칙 (인서터 없음)
- **입력**: 기계를 향한 컨베이어에서 자동 수령. 레시피에 필요한 것만 수락 → 불필요한 아이템은 벨트에서 막힌다(분류기로 푸는 것이 의도된 과제).
- **출력**: 기계를 향하지 **않는** 인접 컨베이어로 배출. 여러 개면 라운드로빈.
- **버퍼**: 재료별 요구량의 2배, 출력 2회분. 가득 차면 `출력 막힘`.
- **상태 표시**: `▶ 작동` / `⏸ 입력 부족` / `⛔ 출력 막힘` / `⚡ 전력 부족`. 줌아웃 시 색 점으로 축약(모바일 필수).

### 6.3 시브(허브) 규칙
- 아이템 수령 시 **재고 저장 + 누적 납품 카운터 증가**를 동시에, 그러나 **분리해서** 처리한다.
  - 건설은 **재고**를 소모, 봉인 해제는 **누적 납품량**을 본다 → 건설해도 진행도가 줄지 않는다.
- **시브는 절대 입력을 막지 않는다.** 재고 상한(9,999) 초과분은 폐기하되 누적 카운터에는 반영 → 허브 앞 벨트 정체가 구조적으로 발생하지 않는다.
- **수동 채굴**: 광석 타일 탭/클릭 시 재고 +1 (소프트락 방지). 철거 시 건설비 100% 환불.

- 타일당 최대 4개, 아이템 위치 `p ∈ [0,1]`, 최소 간격 0.25.

## 8. 전력 시스템

- **도입 시점**: Phase 1(Mk1)은 **무전력**. Phase 2에서 도입되고 Mk2부터 전력 필요 → 물류를 먼저 익힌 뒤 전력이 "업그레이드"로 다가온다.
- **네트워크**: 전력 기둥이 범위 내 건물·기둥을 자동 연결(기둥당 최대 8연결). 연결 그룹 = 하나의 전력망.
- **브라운아웃**: 발전 < 수요이면 만족률(`supply/demand`)만큼 **모든 기계가 비례 감속**. 즉시 정지하지 않는다 → 실패가 부드럽다(필러 4).
- **연료**: 연소 발전기는 벨트로 석탄을 받는다 → 석탄이 물류 대상이 된다. 250 PU ≈ 석탄 4/s → 태양광(Lv12)의 동기.
- **오버레이**: 전력망별 색상, 만족률, 발전/소비 그래프.

## 9. 진행 구조 — 봉인(Seal)

> **UI 표기 원칙**: 요구사항은 언제나 **"무엇을 몇 개"로 평범하게** 제시하고, 잠금 수는 그 아래 **부가 표기**로 보여준다. 테마 때문에 가독성을 희생하지 않는다. (잠금 수를 직접 풀어야 하는 방식은 엔드리스 계약에만 적용 — §5.6)

## 12. 멀티 입력 — 데스크톱 + 모바일

> **원칙**: 하나의 코드베이스, 두 입력 체계, 반응형 UI. 모바일을 "축소판"이 아니라 **동등한 1급 플랫폼**으로 설계한다.
> **구현 원칙**: 입력 추상화 계층(`InputAdapter`)을 **M0에서** 만든다. 터치를 나중에 얹는 것은 비용이 훨씬 크다.

### 12.1 조작 대응표
| 동작 | 데스크톱 | 모바일 |
|---|---|---|
| 팬 | 가운데 드래그 / WASD / 화면 가장자리 | 도구 미선택 시 한 손가락 드래그, 도구 선택 시 **두 손가락** 드래그 |
| 줌 | 휠 | 핀치 |
| 건설 | 좌클릭 | 탭 |
| 연속 건설(벨트) | 좌드래그(축 고정, Shift 자유) | 한 손가락 드래그(도구 선택 상태) |
| 회전 | R | 화면 회전 버튼 / 드래그 방향 자동 정렬 |
| 철거 | 우클릭·우드래그 | 지우개 도구 선택 후 드래그 (광역은 확인 요구) |
| 검사 | 좌클릭(도구 미선택) | 탭(도구 미선택) → 하단 시트 |
| 스포이트 | Q | 롱프레스 |
| 실행 취소 | Ctrl+Z / Y | 상시 노출 ↶ ↷ 버튼 |
| 블루프린트 | Ctrl+C / V | 영역 선택 도구 → 복사/붙여넣기 |
| 오버레이 | P / F / Tab | 오버레이 토글 버튼 |
| 가림 투시 | Alt | 선택 시 자동 반투명 |

**핵심 규칙**: *도구가 선택되어 있으면 한 손가락 = 건설, 두 손가락 = 이동.* 도구가 없으면 한 손가락 = 이동. 팬과 건설의 충돌을 모드로 해결한다(Mindustry 검증 방식).

### 12.2 모바일 레이아웃
- **가로 모드 권장**, 세로 모드도 지원(HUD 세로 적층, 건설 바는 하단 시트).
- 최소 터치 타깃 **44×44 CSS px**. 인접 버튼 간 8px 이상 간격.
- **하단 시트 검사 패널**: 살짝 올리면 요약, 끝까지 올리면 전체 통계.
- 봉인 패널·통계 등 상시 패널은 **접을 수 있게**. 기본 접힘.
- **호버 의존 정보 금지** — 모든 툴팁은 탭으로 도달 가능해야 한다.
- 안전 영역(노치·홈 인디케이터) 대응: `env(safe-area-inset-*)`.

### 12.3 모바일 성능 대응
- **아이템 LOD**: 화면 내 아이템이 임계치를 넘거나 줌아웃되면 개별 스프라이트 대신 **벨트 위 흐르는 텍스처**로 대체. 시뮬레이션은 그대로 유지, 표현만 축약.
- **적응형 품질**: 프레임 예산 초과가 지속되면 자동으로 LOD 단계를 낮추고 사용자에게 알린다(수동 고정 가능).
- 시뮬 틱은 데스크톱과 동일한 30 TPS 유지(세이브 호환·결정성). 부하가 크면 **렌더를 먼저 희생**한다.
- `visibilitychange`에 시뮬 정지 — 배터리·발열 대응.
- 텍스처 아틀라스 ≤ 2048², WebGL1 폴백, 초기 번들 ≤ 3MB.
- 저사양 기기 감지 시 "간소 모드" 제안(그림자·파티클·애니메이션 축소).

### 12.4 PWA / 세이브 연속성
- 오프라인 실행, 홈 화면 추가 지원.
- 세이브는 IndexedDB. **내보내기/가져오기(파일·문자열)** 로 기기 간 이동. 1.0에서 계정 기반 클라우드 동기화는 제외.
- 자동 저장 60초 + 앱 백그라운드 진입 시 즉시 저장(모바일은 탭이 종료되기 쉬움).

## 13. 아트 · 오디오

### 13.1 아트 방향
- **깔끔한 벡터풍 산업 스타일**: 낮은 채도 지면 + 높은 채도 아이템/기계 → 작은 화면에서도 판독 가능.
- 건물은 실루엣 + 컬러 캡으로 구분(제련로=주황 굴뚝, 조립기=청색 팔).
- **소수 모티프**: 아이템 아이콘 귀퉁이에 소수 배지. UI 폰트는 지수 표기가 또렷한 것으로.
- **제작 파이프라인**
  1. 프로토타입: 절차적 드로잉(플레이스홀더).
  2. 이후: Blender 4방향 프리렌더 또는 CC0 아이소 팩.
  3. 스프라이트 아틀라스 1~2장으로 배칭.
- **모바일 판독성 테스트를 아트 승인 기준에 포함** — 실제 폰에서 최소 줌으로 구분되지 않으면 반려.

### 13.2 오디오
- 기계 수에 비례하는 앰비언트 험, 배치/철거/해금 효과음, 봉인 해제 스팅.
- 모바일은 무음 시작 + 첫 입력 시 오디오 컨텍스트 활성화(브라우저 정책).

## 14. 기술 설계

### 14.1 스택
| 영역 | 선택 |
|---|---|
| 언어 | TypeScript (strict) |
| 번들러 | Vite |
| 렌더/입력/오디오 | Phaser |
| UI | DOM 오버레이 (반응형·접근성·i18n에 유리) |
| 테스트 | Vitest (시뮬), Playwright (스모크 + 모바일 뷰포트) |
| 배포 | 정적 호스팅 (GitHub Pages / itch.io) + PWA |

> 후반 렌더 성능이 한계에 부딪히면 PixiJS 등으로 교체할 수 있도록 **시뮬과 렌더를 완전히 분리**한다.

### 14.2 구조
```
src/
  sim/          ← 순수 TS. Phaser import 금지. 결정적(deterministic)
    world.ts        타일 그리드, 청크
    belts.ts        컨베이어 세그먼트 시뮬레이션
    machines.ts     기계 상태머신
    power.ts        전력망 분할·만족률
    sieve.ts        재고 / 누적 납품 / 봉인
    save.ts         직렬화·마이그레이션
  factor/       ← 서명 시스템 (sim·UI·툴이 공유)
    signature.ts    서명 계산, 곱/거듭제곱, 인수분해 표기
    solver.ts       목표 생산량 → 기계 대수, 병목 판정
  data/         ← 데이터 주도. 코드 수정 없이 밸런싱
    items.ts / recipes.ts / buildings.ts / seals.ts
  render/       ← Phaser 씬, 아이소 변환, 스프라이트, LOD, 오버레이
  ui/           ← 반응형 HUD (데스크톱/모바일 레이아웃 공유 컴포넌트)
  input/        ← InputAdapter (포인터/터치 통합) + Command 패턴
  tools/        ← 밸런스 계산기, 맵 시드 미리보기
tests/
```

### 14.3 시뮬레이션 핵심
- **고정 30 TPS**, 렌더 60fps + 보간. 지연 시 최대 N틱 따라잡기 후 슬로모션(누적 방지).
- **벨트 세그먼트화**: 연결된 직선 벨트를 하나의 라인으로 묶어 헤드부터 갱신.
- **활성 집합**: 정체/유휴 기계는 이벤트 발생 시까지 갱신 생략.
- **Command 패턴**: 모든 변경은 커맨드 → Undo/Redo, 이후 리플레이·Web Worker 이관 가능.
- **시드 RNG(mulberry32)**: 맵·계약 생성 결정적. 시드 공유.
- **서명 연산**: 큰 정수를 쓰지 않고 **소수별 지수 배열**(`Int32Array` 길이 6)로 표현한다. 곱셈=덧셈, 거듭제곱=스칼라 곱 → O(6). BigInt 불필요.

### 14.4 세이브
- JSON → LZ 압축 → IndexedDB. 자동 저장 60초 + 백그라운드 진입 시.
- `saveVersion` + 마이그레이션 체인. 밸런스·레시피 변경이 구버전 세이브를 깨뜨리지 않게.
- 서명은 **저장하지 않고 레시피에서 재계산** — 밸런스 변경 시 자동 반영.

### 14.5 성능 목표
| 항목 | 데스크톱 | 모바일 |
|---|---|---|
| 프레임 | 60fps | 60fps (3~4년 전 중급기 30fps 하한) |
| 규모 | 벨트 5,000타일 / 기계 500기 / 아이템 10,000 | 벨트 2,500 / 기계 250 / 아이템 4,000 (초과 시 LOD) |
| 시뮬 1틱 | ≤ 10ms | ≤ 16ms |
| 초기 로딩 | ≤ 3초 | ≤ 5초 (3G 아님, LTE 기준) |
| 번들 | ≤ 5MB | ≤ 3MB (초기) |

### 14.6 테스트 전략
- 시뮬: 벨트 처리량, **아이템 보존(생성·소멸 없음)**, 루프 데드락 없음, 브라운아웃 비례 감속, 시브 비차단.
- **서명 불변식**: ① 모든 레시피는 산출 1개(규칙 R1) ② 서명에서 역산한 원자재 = 레시피 트리 전개 결과 ③ 잠금 수 = 요구 아이템 서명의 곱.
- 세이브 왕복, 시드 결정성.
- Playwright 모바일 뷰포트 스모크: 탭 건설 / 드래그 벨트 / 두 손가락 팬 / 하단 시트.

## 15. 개발 로드맵 (1인, 파트타임 가정)

| 마일스톤 | 기간 | 완료 기준 |
|---|---|---|
| **M0. 셋업** | 1.5주 | Vite+TS+Phaser, 아이소 변환·카메라·타일 피킹·고스트 배치, **InputAdapter(마우스+터치 동시)**, 반응형 셸 |
| **M1. 첫 루프** | 2주 | 채굴기 → 벨트 → 시브. 벨트 시뮬 테스트 통과. 벤치마크 씬 |
| **M2. 가공 + 서명** | 2.5주 | 제련로·조립기·레시피·분배기·언더패스, **`factor/` 모듈 + 인수분해 뷰 1차** |
| **M3. 전력 · 봉인** | 2주 | 발전/기둥/브라운아웃, 봉인·해금, HUD·검사 패널·통계 |
| **M4. 모바일 통과** | 1.5주 | 실기기에서 Lv1~4를 터치만으로 완주. 하단 시트, LOD, PWA, 성능 목표 달성 |
| **M5. MVP** | 2주 | 맵 생성, 세이브/로드, 맥락 힌트 → **Lv1~12 클리어 가능 (데스크톱·모바일 양쪽)** |
| M6. 콘텐츠 | 3주 | Phase 4~5, 블루프린트, 오버레이, 밸런싱 |
| M7. 폴리시 | 2주 | 아트/사운드 교체, 최적화, 베타 공개 |

**MVP(M5) 정의**: 처음 접속한 사람이 튜토리얼 없이 30분 내 Lv4에 도달하고, 세이브 후 재접속해 이어하며, **폰에서도 동일하게 가능하다.**

> 모바일 동시 지원으로 v0.1 대비 약 **3주** 증가했다. 대부분 M0의 입력 추상화와 M4의 UX 검증이며, 나중에 얹는 것보다 저렴하다.
